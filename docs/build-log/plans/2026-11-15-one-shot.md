## Rules that are never broken

If a step seems to need one of these broken, skip the step and write it in the log.

1. Never open, print, copy or edit `.env` in the backend. Never connect to a hosted database. Never run a `DROP`. For the whole session, every command you run in the backend, tests included, has `DATABASE_URL` set to SQLite in its environment (see "How to run things"), so nothing can reach the hosted database by accident.
2. Never merge a pull request. Never push to `main`. Never force-push or rewrite history. You open pull requests and the reviewer merges them. A merge deploys.
3. No team member's name in code, tests, comments, commit messages, documents or the log. Use roles: backend owner, frontend owner, data owner, hardware owner, deployment owner, reviewer.
4. Build what the plans say and nothing else. No restyling, no refactor a step does not ask for, no new dependency.
5. `command_center/` never imports the ship's tables. The Earth page never asks `/api/base`.
6. The app's own words never say "machine learning", "trained", "validated" or "predicts illness".
7. Stage files by name. If `git status` shows files you did not touch, run `git diff --ignore-cr-at-eol --stat`: an empty answer means line endings only, and those files are not staged.
8. Leave these alone: backend Task 4 Steps 2 and 3 (they are for people), backend Tasks 6 and 7 (they wait for the data owner: if a new branch of theirs is on origin, note it and do not merge it), backend Task 8 Steps 3 and 4.
9. Each backend task adds its line to `AI_USE.md` in the format the file already uses.

## How to run things

- **Backend tests.** In `LightTime-backend`, with `.venv` active: `python -m pytest -q`. PowerShell: `$env:DATABASE_URL='sqlite:///lighttime.db'` first. bash: prefix the command with `DATABASE_URL=sqlite:///lighttime.db`.
- **The ship.** Start it in the background, one process only, on port 5000. PowerShell: `$env:DATABASE_URL='sqlite:///lighttime.db'; $env:LIGHTTIME_MORNING='1'; python app.py`. bash: `DATABASE_URL=sqlite:///lighttime.db LIGHTTIME_MORNING=1 python app.py`. Values set this way win over `.env`, which is why `.env` never needs to be read. Restart the ship after every backend task. `POST /api/base/reset` returns it to 06:30 whenever a check needs a fresh morning.
- **The console.** In `LightTime-frontend`: `pnpm install` once. Only one `pnpm dev` runs at a time, on port 3000. Live mode: start it with `NEXT_PUBLIC_API_URL=http://localhost:5000` in its environment. Seed mode: start it with that variable absent. Do not create `.env.local` until Phase 4, so the two modes stay under your control. If a `.env.local` already exists and sets that variable, rename it to `.env.local.off` for the run and put it back in Phase 4.
- **Check lines in the plans are PowerShell** (`irm`). From bash, run them as `powershell -NoProfile -Command "<the line>"`, or make the same request with `curl`.
- **Browser checks.** Use the playwright skill with a headless browser on `http://localhost:3000`. For each check a step names, assert the text or state it names, and save a screenshot in a `lighttime-run-shots` folder beside the run log. Keep these scripts outside both repos: the plans ask for no test files of this kind.
- **The voice.** Before the page loads, replace `window.speechSynthesis.speak` with a counter. Click "Sound on", start the story, and assert the counter reads 1 after the first sentence and does not climb once a second. Write in the log that nobody listened to it.
- **The seed mode check** (console Rule 2), after every console task: stop the live dev server and start it in seed mode. Assert: four crew cards; the header reads `Ground link 0.6 s one-way`; the CO2 tile reads 2.6; A1 can be acknowledged and sent; about 8 seconds later a reply appears by itself; "Accept plan" adds four reminders. Then go back to live mode.

## When something fails

This is the unattended form of the plans' stop rules. Where a plan says "stop and report", do this instead.

- **A step's code does not work as written.** Debug it, make the smallest fix that keeps the intent, log the difference. Three attempts at most.
- **Park the task** after three attempts, or when an old test fails in a way the step does not name, or when the seed mode check cannot be made to pass. Put the repo back to its last green commit (`git stash -u` with the task's name is fine), write in the log what you tried and what you saw, and go on to the next task that does not depend on it.
- **What depends on what.** Console: 2 needs 1, and every later task needs 2. 8 needs backend 1. 9 needs 8 and backend 3. 11 needs nothing. Backend: 1, 2 and 3 stand alone, except that 2 adds its tests to the file 1 creates.
- **End the run and report** when: a baseline fails in Phase 0; git shows a conflict, a detached HEAD or code changes you did not make; or going on would break a rule above.

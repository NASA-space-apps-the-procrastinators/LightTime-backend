## If something goes wrong

| What you see | What to do |
|---|---|
| A count differs from the plan | Read the failure. If it is not one of the kinds the step names, stop that session and ask. Do not let it change a route to pass an old test |
| The console's type check fails on the import between the store and `ship-api.ts` | Move the schemas into `src/lib/ship-schemas.ts` and import from both, as the console plan's self-review says |
| The page under `/command-center` will not build | Read the routing guide `AGENTS.md` points to. The page file is three lines; the rules around it are what differ in this version |
| LIGHTTIME's card never shows | The backend is older than its Task 1: `raised_by` is missing. Restart Terminal 1 on the new code |
| Nothing is spoken | Press "Sound on" first: browsers allow speech only after a click. The sentence is on the card either way |
| A1 is not there after a restart | The backend was started without `LIGHTTIME_MORNING=1`, or is running more than one process |
| A crew card shows the built-in values while the others show the ship's | That person's answer from the ship held an empty value. Read `(irm http://localhost:5000/api/base/crew/<id>).today` |
| The log page takes a second to fill the first time | Expected: the ship reads a month of minute rows once |
| `python app.py` fails at start with a database error, or hangs | `.env` still has the hosted database's `DATABASE_URL`, and this network is not on its list. Remove the line: local runs use SQLite |
| The hosted console shows the built-in demo after a merge | Expected. It is built with no ship address until the deployment owner passes one (console plan, Task 11) |
